# 内置问答与连续执行

本约定适用于主入口及内部阶段的文档地址、需求冲突、设计方向、参考、全局设计基础、本地目录、平台和目标位置等输入。用户已提供的信息直接复用；修改 skill 本身时，不启动设计访谈。

## 所有宿主共用的交互契约

宿主适配只转换工具协议，不改变用户体验和业务校验：

1. 对外只调用 design-to-handoff，不让用户选择内部阶段技能。
2. 所有缺失输入优先用宿主的原生问答；选择题支持可点击选项及自由输入，路径/链接题收集真实值。
3. 首次先单独问【需求文档｜必填】，取得有效来源后再单独问【补充文档｜可选】；不能合并、颠倒或把补充题变成必填。
4. 需求题不接受空白或跳过；补充题允许明确跳过、“无”或主动空白提交。已知答案不重复问。
5. 题目已展示、工具已返回、默认预选或等待超时均不是已作答；实际收到答案后自动继续。

以下工具名和示例用于协议适配，不代表仅这些宿主需要遵守此契约。没有列出的宿主也必须先发现自身原生问答能力；真实缺失时说明限制，不声称已经实现原生控件。

## 选择实际可用的问答工具

先检查当前会话的工具说明及模式限制，使用宿主内置的结构化问答。统一的交互要求是“原生问答 → 选项或自由输入 → 接收答案 → 继续当前流程”，不依赖 OpenAI、某个模型供应商或固定工具名。工具名称只是路由提示，不是必须存在的接口：

- Codex 暴露 `request_user_input_async` 时优先使用，常见完整名称为 `functions.request_user_input_async`。提交后调用会立即返回，答案随后作为用户消息到达；调用返回不代表用户已回答。
- 只有当前模式明确允许时，才使用同步 `request_user_input`。例如说明标注 Plan mode only 时，不能在 Default 模式调用，也不要仅为显示问卷切换模式。
- Claude Code 的 `AskUserQuestion`、OpenCode 的 question 或其他宿主的对应能力，以实际工具契约为准。不要臆造工具名或照搬另一宿主的参数。
- CodeBuddy **IDE/插件**先读[插件问答适配](codebuddy-plugin-input.md)，识别原生 `ask_followup_question`；它的 `question` / `options` 与 Codex 的 `title` 文本题不同，不能照抄下面的 Codex 示例。CodeBuddy Code **CLI**另按实际暴露的 `AskUserQuestion` 契约执行，两者不可混用。
- WorkBuddy 桌面端按[专用适配](workbuddy-input.md)优先调用实际提供的 `AskUserQuestion`，不要仅因产品相近就套用 CodeBuddy 插件工具名。待答卡片不能当执行权限自动批准。
- Cursor 及其他兼容宿主同样先识别内置提问/表单能力，包括直接暴露的工具或宿主明确支持的交互入口；不因不是 Codex 就默认退回文字问答。未暴露或当前模式不允许的能力不能凭产品名称假定可用。
- 确实没有当前模式可用的内置问答工具时，才说明限制并改用普通聊天提问。技能文本不能自行创建原生问答控件，也不能保证所有宿主都具有相同等待体验。

## 选项及自由输入

- 每题聚焦一个决策主题；基础阶段可将同主题的相近参数组成方案或组内字段，提供少量真实可执行的选项；有建议时放在首位并解释理由。可选阶段提供“跳过”或“暂不上传”。
- 保留自由输入入口，让用户能指定路径、链接、数值或完全不同的方案。宿主自动提供“其他/自己输入”时，不重复添加同名选项；没有该入口但支持文本题时，用文本题补充。
- 地址、目录、链接等开放信息在宿主支持时直接用文本题；宿主要求选项时使用其原生选项加自定义输入，不省略必需字段。不强行编造候选路径，也不先问一次“本地还是在线”再收集地址。
- 按工具限制拆组。全局设计基础每轮只处理一组相近参数，可用一个组合题或同组多个字段收集，回答后再问下一组；不同组不合并在同轮。已选“全部推荐”不再逐组提问。其他阶段可按容量分组；选项最多三项就将 Figma/Penpot/两者放在“上传平台”子问题，先用“上传/暂不上传”确定是否需要该问题。
- 截图、附件使用宿主附件入口，密码和 OAuth 授权码使用正式授权界面。Penpot MCP key 是本技能明确支持的专门输入：按[云端交付](cloud-handoff.md)单独询问，优先秘密输入；用户要求以问答提供且宿主只有文本题时，用独立文本题接收，不回显，不混入设计需求或交付记录。

以下仅为 Codex 异步接口的参数示例；其他宿主使用各自 schema 实现相同交互，不需要安装 OpenAI 工具，也不照抄这些参数。仅在实际工具契约与下面一致时使用：

首次收集文档分两次调用；已提供的题不重复询问。第一题【需求文档】必填，Codex 支持省略 `options` 显示自由输入：

```json
{
  "questions": [
    {
      "title": "【需求文档｜必填】请填写需求文档的文件路径、目录或在线链接。"
    }
  ]
}
```

收到有效需求来源后，再单独调用第二题【补充文档】；自定义输入区可直接填写地址，不必先选“填写”再重新提问：

```json
{
  "questions": [
    {
      "title": "【补充文档｜可选】如有补充文档，请在自定义输入区填写文件路径、目录或在线链接；也可跳过。",
      "options": ["跳过（无补充文档）", "填写补充文档地址"]
    }
  ]
}
```

必填由接收答案后的来源检查落实；不要向不支持该字段的工具添加 `required`。补充题的明确跳过、“无”或已提交的空白都表示没有补充；工具刚返回、空答案容器和未提交的默认预选仍是待答。只选择“填写地址”但未填实际地址时，补问该题的地址，允许补充题改为跳过。

方向选择，用户也可在工具自带的自由输入区描述其他风格：

```json
{
  "questions": [
    {
      "title": "界面采用哪种视觉风格？也可自行描述其他风格。",
      "options": ["由你根据需求推荐", "简洁商务", "紧凑工具"]
    }
  ]
}
```

示例中的选项仅供组织问题，不能作为所有项目的固定偏好。

## 等待与继续

1. 发起问答时保留当前阶段和缺失字段，不发送 final/结束本轮消息来等待输入，不要求用户再说“继续”或重新调用 skill。
2. 同步工具等待回答后直接处理。异步工具提交后，可继续做不依赖答案的工作；没有独立工作时，用宿主支持且可被用户输入唤醒的等待机制让出执行，单次等待不超过 60 秒。不要循环空查、重复发送同一问卷或用无关工具拖住会话。
3. 用户回答到达后，合并选项与自由文本，自由文本中的明确修正优先。实际路径缺失时只补问路径；若用户已在普通消息里补齐，不再重复问。收到取消或修改范围的指令时按用户最新意图处理。
4. 必填信息未到达时保留待答状态，不执行依赖步骤；等待超时、空结果和默认预选都不构成用户回答或授权。可选问题的无回答处理遵守宿主规则，绝不能据此扩大上传或分享范围。
5. 仅在工作完成、用户主动停止，或真实能力缺口使当前流程无法继续且已说明时结束。若宿主没有保持执行并等待的机制，明确说明这一限制，不假称 skill 能强制会话持续运行。

## 设计前已有目标问答

两道文档题之后先按[前置上下文](design-context.md)识别设计类型。补充/修改必须在方向和生成前单独问已有链接、读取基准并解决冲突；已知链接不重复问。仅新建可以把上传平台留到设计后。需要读取已有目标的授权/密钥问答也前置，不能把未读样式当作可选参考跳过。

## 参考后的基础问答

参考已分析或明确跳过后，按[全局设计基础](stages/foundations.md)进入模式题，再按相近参数分组确定或一次采用推荐。本组“跳过”表示本组未定参数推荐；单参数补问时跳过只影响该参数，“剩余全部推荐”表示未定适用项推荐；未提交/默认预选/超时不表示已选择。组内允许一次修改多个参数；题干明确“未改项沿用已展示推荐”后可直接合并局部修改，其余未授权时只补问缺项。已指定/继承值保留，组内参数分别记录来源和待答状态。已有项目只问缺项。具体推荐值与来源必须进入正式规范，不只留问答记录。

## 平台授权问答

设计前读取已有目标，或新建设计验收后选择 Figma/Penpot 时，按[云端交付](cloud-handoff.md)发现实际连接和浏览器能力。需要授权时，真实打开/启动授权入口后再显示“完成授权 / 重新打开授权 / 暂不上传”的原生题；已连接且身份、访问探测通过时直接继续。用户点完成后重新验证，不把问卷提交当成平台授权已生效。

Penpot MCP key 的问题与“完成授权”分开：密钥题只接收实际密钥（或暂缓），完成题用于恢复授权探测。原生题未提供掩码能力时不能谎称输入已被隐藏，也不承诺宿主不会保留聊天历史。由技能负责避免主动回显、将秘密写入仓库或把它拼进 shell 参数。

## 行为验收

验收看实际工具调用与衔接，不看文字是否画出了菜单：

- 缺少两类文档：第一轮只问【需求文档｜必填】；有效来源到达后，第二轮只问【补充文档｜可选】。两题分别接收答案，不要求“继续”。
- 需求题空白、回答跳过或只选“填写地址”：保持需求待答，不进入摘要和设计；补充题明确跳过/无/主动空白提交：记录 skipped 并继续。
- CodeBuddy 插件有 `ask_followup_question`：发起真实原生调用，`questions` 是对象数组且每题有 `question` 和非空 `options`；返回“已展示”但 `answers` 为空时仍待答，不调用完成工具。
- 文档已提供：跳过首次地址题，读取文档后只问缺失方向；选择推荐或输入自定义字号均能被采用。
- 当前模式禁止同步问答但有异步接口：使用异步接口；调用返回后没有答案时，不进入依赖阶段。
- 多于工具题数/选项数限制：拆组，保留自定义输入；跳过参考、明确不保存或暂不上传后自动进入相应下一步。
- 参考结束/跳过：先进入全局基础模式题；分组模式将字体/字号/行高等相近项同轮收集，不同组分开；本组跳过只影响该组未定参数，局部修改保留已指定值，剩余推荐不重置已答组；已有答案不重复问，无答案不进入依赖步骤。
- 同站扩展：先读取文档/云端规范及相关设计，继承版本，只补缺项；参考配色不静默覆盖已有品牌色。
- 只要求修正这个 skill 的交互：修改并检查 skill，不向用户索取本次设计需求文档。

修改后的语法与链接检查不能冒充已完成上述宿主界面实测。
