# 云端交付：浏览器授权、自动创建与追加设计

所有宿主、Figma 和 Ardot 共用本流程；协议差异在平台内部说明中适配。设计前已有目标的读取按[前置上下文](design-context.md)执行，此时不需要预先有设计源文件；真正云写入前的输入才是已验收的设计源文件和 viewId 清单。选择平台后由智能体负责创建、命名、上传/构建和读回，不能把“你去建目录、手动导入再命名”当成默认完成路径。安装技能只提供流程，不自行产生 OAuth 客户端、浏览器工具或平台写权限。

## 平台选择先于连接结论

设计预览验收后，即使初始工具列表没有 Figma/Ardot，也先发起原生上传选择题。用户未明确暂缓时，不能以“当前会话没有可用连接”作为结束语或自行只交本地文件。已有明确平台/绑定目标直接复用，不重复提问。

先用“上传 / 暂不上传”确定交付意愿，再用仅含 **Figma / Ardot** 两项的平台题收集目标；已明确选择直接复用。不提供蓝湖、Penpot 或“两者”选项，不按当前已连接名单过滤平台。用户主动要求两平台时视为明确扩展范围，各自完成完整流程并独立记录。

记录 platform_selected 后，必须先读取对应的[平台流程](stages/publish-figma.md)或[Ardot 流程](stages/publish-ardot.md)，并加载宿主要求的相关技能，再执行发现、连接、授权与探测。初始无工具是 discovery_pending；真实需要用户授权是 awaiting_user；只有实际连接引导/发现后仍有明确缺口，才记录 blocked。本机没安装客户端不能成为跳过理由；优先检查官方云端 MCP 和宿主自定义连接入口。用户取消某平台授权则停止该平台，不换路绕过取消。

## 先确定交付意图

设计类型与已有目标在生成前按前置上下文确定。上传阶段复用这些信息，只在用户中途改目标/范围时补问下表受影响项；不能在本阶段首次询问是否补充已有设计：

| 问答 | 选项/输入 | 接收后动作 |
|---|---|---|
| 这次如何交付？ | 新建设计（自动创建文件）；补充已有项目/文件；暂不上传 | 已有目标链接时直接采用“补充”，不重复问模式 |
| 补充到哪里？ | 项目、Design 文件、页面或画板的实际链接，可自由输入 | 验证实体类型与实际身份，不能只凭链接名称判断 |
| 多个可写团队/空间 | 展示实际名称与身份；允许指定其他目标 | 沿用已给团队；唯一可用落点直接采用，不要求用户新建目录 |

不默认强制新建云端 Project/目录。“新建设计”默认是创建一个新的设计文件；Figma 可放到选定账号的个人草稿区，Ardot 放到真实可用的项目。用户明确要求新的 Project/目录时，智能体用实际管理工具或可控浏览器创建，不能把创建任务转交用户。没有创建 Project 的能力但能创建草稿文件时，问答展示具体替代落点，让用户选择，不能谎称创建了 Project。

默认文件名由当前需求中的项目名生成，例如“项目名 · 设计交付 · YYYY-MM-DD”；页面按业务、状态和终端命名。用户已给名称则采用；没有名称也不阻塞，不要求用户去云端改名。同名文件不是可覆盖的授权，新增时创建独立文件并记录其真实 ID。

## 连接与浏览器授权

1. **复用连接**：先发现工具，并做实际只读探测。可确认账号及后续写入能力时直接继续，不重复开授权页。只有浏览器登录态或只能读取文件，不能证明可写。
2. **发现并启动连接**：工具缺失时先发现宿主可用的官方插件/MCP 连接与授权入口。WorkBuddy 先按[原生连接适配](workbuddy-input.md#平台选择后的连接引导)加载并调用 workbuddy_request_mcp_connection；有宿主强制连接引导时，不先输出手动设置教程、索取密钥或尝试替代来源。原生连接卡片接管时等待其结果，不叠加浏览器/密钥流程；只有无受管卡片而采用直连时，才由宿主连接机制启动认证。若返回真实授权 URL，用可用浏览器工具打开可见窗口/标签页。没有 URL 时只打开实际官方登录/连接页，并明确它是登录或配置页；不能臆造 OAuth URL、client_id、回调或第三方授权服务。
3. **交给用户完成账号步骤**：账号登录、信任、二次验证和同意 OAuth 授权由用户处理。智能体不读取密码、Cookie 或授权码，不代替用户点击同意。Figma 与 Ardot 的远程 MCP 走各自正式授权，不沿用旧版密钥问答。浏览器由宿主工具控制，不使用只适用于作者系统的打开命令。
4. **原生问答等待**：宿主连接卡片已经等待授权时复用该卡片，不叠加第二道“完成授权”题或提前结束；按其返回结果继续。没有这种卡片、而浏览器/宿主授权入口已经打开或已提供时，发起“请在打开的窗口完成平台授权，完成后选择下方选项”。选项为“完成授权”“重新打开授权”“暂不上传”，并保留自由输入说明问题。按宿主参数限制组织题目；不中断为 final，不要求额外发送“继续”。
5. **点击后验证**：“完成授权”只是要求检查的用户事件，不是认证证据。重新探测连接、当前账号和目标访问能力。需要时发现重新暴露的工具，区分账号认证、MCP 连接、目标文件可写三种状态。失败时指出具体未完成项；是否允许重试按宿主规则，WorkBuddy 的 failed/skipped 本轮不再次请求同一服务，不能重新开浏览器或索取 key 来绕过取消。允许恢复时再提供重试/重新授权/暂缓；不能直接开始云写入。
6. **只自动化可用能力**：浏览器自动化可负责进入项目、创建和命名文件、打开目标文件及非敏感连接操作。账号登录、信任及授权由用户完成，服务配置按所选平台适配执行。宿主没有自动发起认证能力时，直接打开其真实连接设置，不要求用户自行找教程。没有可用写入路线时给出实际缺口与继续点，不把手动导入包装成自动上传成功。

Figma 官方远程 MCP 为 `https://mcp.figma.com/mcp`，Ardot 为 `https://ardot.tencent.com/mcp`，均不以本机客户端为前提。宿主已声明依赖且提供原生受管连接时优先使用；没有候选则核查宿主正式的自定义远程 MCP 配置能力，按所选平台说明添加/启用并触发 OAuth。MCP 服务地址不是授权 URL；不虚构凭证或沿用旧版 Penpot key 题。配置只合并本服务，不覆盖其他连接。

新增或修改 MCP 配置后，使用宿主实际支持的重连/工具刷新，再重新发现工具。若宿主必须重载或重启才会暴露新工具，在原生问答中说明这一具体限制，保留非敏感继续点和设计源文件；不能虚构工具已出现，也不能把恢复操作变成要求用户手动导入。

账号就绪与文件上下文就绪分别检查。Ardot 云端通过真实文件/节点链接定位，不要求本机活动文件；新文件尚未创建时先确认账号，再由实际 MCP 或浏览器创建并命名，之后验证目标。只有明确采用本地 MCP 时才检查客户端和当前活动文件，不能混成认证失败。

## 何时才可以报告连接阻塞

必须已有平台选择/明确目标，并有真实发现及必要连接引导的结果。记录缺的是哪一项：未声明也未发现对应服务、连接入口不可用、用户取消、认证失败、工具刷新需重载、目标只读，或认证成功但没有 Design 图层写入能力。不能把这些都压成“没有连接”。

阻塞时保留设计/规范、选定平台、已发现服务的真实标识、工具结果摘要、已创建 ID 和继续点，提供与该结果相符的恢复入口；不回显授权 URL 中的凭证。需要安装或启用时使用宿主实际返回的安装/连接卡片，缺少该能力才说明具体设置入口。不要虚构 serverName、serviceId 或授权页面。尚在待答/待授权时保持等待，不把它写成终止阻塞。

## 新建设计：用户授权后自动完成

- 先得到账号/团队上下文；需要团队选择时在原生问答中选真实团队。
- 工具能创建文件则直接创建。若只能写现有文件，则由智能体在可控浏览器中创建、命名并取得文件链接，再交给写入工具；不要求用户完成这一步。
- 自动设置文件名与页面名，记录新文件、项目、页面 ID。之后的重试复用这些 ID，不再反复新建。
- 目标文件可写及文件上下文验证通过后，逐页构建真实文字、布局、图标和独立图片图层；遵守当前宿主平台技能要求。这里的“上传”可以是原生构建，不限定为导入某种文件。
- 云写入后实际读回页面、图层和关键属性，并看远端整体预览。返回可打开的设计文件/画板链接。新建空文件、打开了浏览器、本地 HTML 或导入按钮被点击都不算交付完成。

## 补充已有设计：先定位，再追加

用户可以给团队项目、文件、页面或画板链接。先通过真实工具/浏览器读回其名称、类型、账号/团队和可用权限，再决定动作：

| 目标类型 | 默认追加方式 | 必须保留 |
|---|---|---|
| Project/项目链接 | 在该项目自动新建设计文件，不写进任意现有文件 | 项目下其他文件与权限 |
| Design 文件链接 | 在文件中新增业务命名的页面；页数受限时先给出在现有页新增独立区域的方案 | 原页面、组件和已有画板 |
| 页面/画板链接 | 在该页可用空白区域追加一组独立画板，或按用户指定新增页面 | 参考/锚点节点及其内容，不默认替换 |
| 明确要求更新指定画板 | 按已确认的节点与改动范围修改；有多个候选或覆盖范围不清时先展示具体差异再问 | 无关节点与用户未授权删除的旧内容 |

已有文件不是默认覆盖目标。首次说明落点和追加范围，让用户在目标选择题中确认该具体方案；用户已明确给出落点和追加方式时，不再次审批相同动作。覆盖、删除旧画板或修改全局共享组件不得从“补充设计”中推断；有明确授权则按授权范围执行，不机械重复确认。

既有颜色、字体、组件和布局规则必须在设计前已读取并固定。上传前仅复核目标、权限和相关 revision/基线摘要。不得因为用户最初没主动给链接而跳过前置收集；若用户到此时才主动改成补充已有设计，视为范围变更，返回前置上下文并说明可能的局部返工。

正常流程的风格冲突已在生成前解决。只有目标/需求改变或远端相关基准发生实质变化，导致已验收设计与当前风格冲突时，先展示受影响范围、具体差异和局部预览，再用原生问答决定“沿用已验收方案”“适配已有项目风格”“自定义调整”。用户已明确授权沿用既有规范时直接按授权执行；无实质视觉变化的组件映射也不重复审批。只调整受影响部分，展示结果并完成本地覆盖/视觉检查后再写入；不能静默推翻已验收设计，也不修改共享组件来迁就新图。

写入前记录目标身份与本次范围的基线（既有页面/相关节点 ID、样式引用、必要截图）。新画板避开已有内容，使用新页面或计算可用空白区域；同名画板只作为候选，不能直接删改。记录 viewId → 远端节点映射，恢复时以真实 ID 读回，不仅靠名称匹配。

Ardot 本地 MCP 切换聚焦文件可能改变上下文；每批写入前对照绑定的 fileId/pageId。云端 MCP 以实际传入的文件/节点上下文为准，不因无本机活动文件而失败。发现目标改变先恢复已授权目标，再探测并继续。

## 全局规范随设计归档

按[项目规范约定](project-style-contract.md)在同一已授权文件创建/追加可编辑“设计规范”页或独立区域，保存本次完整全局决策、版本、token 值/别名与规则、局部例外及复用入口。记录其稳定节点 ID，重试复用该 ID；不覆盖其他规范版本，不因页数限制省略规范。

上传并读回实际样式后，把设计/规范链接、版本映射、真实平台样式/变量 ID、差异和验证状态写回规范及所选本地文档。源值与远端值不一致须修复或标明降级/待验收，不能悄悄改全局标准。两平台共用逻辑规范版本，各自记录实际映射和限制。图已上传但规范未持久化时分别报告状态，保留恢复点，不能称全流程完成。

## 运行状态与恢复

在会话记录中分别维护：

- deliveryMode：new / append / update；目标 URL、类型、账号/团队、projectId/fileId/pageId/nodeId。
- platformSelection：pending / selected / deferred，所选平台与实际回答；不得由工具列表空自动改为 deferred。
- connection：discovery_pending / needs_auth / awaiting_user / account_ready / target_ready / blocked；declaredServerName/pluginName、实际发现结果、原生连接调用与返回状态、阻塞类别；browserOpened、userReportedComplete、actualProbe、可用写入路由。只记录非敏感身份，不记录令牌与授权 URL 中的秘密。
- progress：已有设计为 context_selected → context_reading → context_ready → local_ready → target_revalidated → uploading → remote_verified；新建无需已有目标上下文，依次 local_ready → platform_selected → connection_discovery → awaiting_user（需要时）→ account_ready → target_ready → uploading → remote_verified；已有有效连接可省略授权等待，不能省略实际探测。中间可以进入 awaiting_user 或 blocked，不能跳过所需的上下文、身份及权限验证。
- plannedChanges / createdIds / baseline：预定追加范围、新创建节点、已有内容基线、成功与待补 viewId。

“完成授权”后 actualProbe 失败仍保持连接待处理；新文件尚不存在时允许账号就绪后创建文件，再检查目标上下文。账号已连接但文件只读时只处理目标编辑权限，不能无限重做 OAuth。

部分失败先读回已创建内容，只补缺失或修复受影响节点；不重复创建文件/画板。超时不代表创建失败，先按工具返回的 operation/capture ID 等待真实结果，再用已知节点 ID 与目标范围基线定位新增内容。没有返回节点 ID 时，对比限定父容器和基线、内容及布局判断；不能仅因同名或一次未读到节点就重建。仍无法确定超时写入结果时，保留该项为 unknown/pending，暂停这一项并说明继续点，不猜测“确实缺失”。明确根因修复后最多重试两次，仍失败保留链接、ID 和继续点。保留当前已验收本地源文件，不能以“未选择本地副本”为由丢失唯一可恢复产物。

连接就绪、空文件已创建、上传完成、原生属性已验收、第二账号已验收分别报告。只有远端读回与预览通过才能称“已上传并检查”；多人查看仍按[共同验收](evidence.md)单独判断。

## 演练验收

- 初始无平台工具 + 尚未选平台：先发真实平台选择题，选后启动宿主连接卡片/授权；不能先结束或过滤未连接平台。
- WorkBuddy 已声明但工具未加载：ToolSearch 加载原生连接工具 → 用精确 servers 请求选定服务 → connected 后重试原操作；failed/skipped 本轮不再请求同项。
- WorkBuddy 无声明/无对应连接器：保留平台选择，实际发现候选并用宿主安装/连接入口；没有候选或入口才说明具体缺口，不编造服务名。
- 已认证但目标只读/缺少写入：报告对应能力问题，不重复 OAuth；另一平台已选且可交付时继续该平台。
- 未连接 + 新建设计：宿主原生连接卡片，或无受管连接时的可见浏览器/完成授权题 → 真实探测 → 智能体创建/命名/构建 → 远端读回；不要求用户建目录、导入或改名。
- 已连接 + 新建设计：跳过授权等待，直接自动创建并写入。
- 用户点完成但探测失败：不写入、不伪称已授权；问答保持可恢复。
- 补充/修改但尚无链接：在生成前发起已有链接题，未读规范或冲突待答不生成正式页面；不能到上传时才索取。
- 已有 Project、文件与节点链接：生成前定位基准和处理冲突，上传分别落入新文件、新页面、新区域，默认不覆盖旧内容。
- Ardot 无本机客户端：继续官方云端连接/OAuth；云端按文件链接定位。本地模式新文件尚未创建或活动文件改变，分别处理创建和上下文恢复，不混作授权失败。
- 写入中断后恢复：复用真实 ID，只补缺失项；不产生多个同名空文件。
