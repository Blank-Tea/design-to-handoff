# 设计生成与验收

这是 design-to-handoff 的内部阶段说明。需要用户输入时遵守[内置问答约定](../interactive-input.md)，沿用当前阶段、待答问题和已有答案。

输入为已读需求、[前置上下文](../design-context.md)、已回答或授权推荐的方向、可空参考、[全局设计基础](foundations.md)解析结果与规范版本、本地保存选择。新建上下文可为 not_applicable；补充/修改必须已有目标、已读规范和已决冲突（context_ready），或用户明确授权 draft_only。链接缺失/不可读、基准不明、关键冲突待答时不生成正式页面，返回前置阶段。

基础阶段未完成或存在未决实质冲突时不开始正式生成。用户已授权推荐的项需先转成具体值；同站扩展固定 baseVersion 和局部例外，不能生成时另起一套风格。

## 生成

1. 先形成设计文档，结构见[文档约定](../session-contract.md)，全局规范与 tokens 按[项目规范约定](../project-style-contract.md)落档。context_ready 或新建正常路径才作为正式交付版本；draft_only 的文档、页面和预览均标为草稿，不能当既有规范已验收。浓缩需求不是设计文档替代。
2. 用 HTML/CSS 表达全部约定页面/状态。无需真实后端，不发送表单或生产交易。每个 viewId 保留可重现的视口和内容。
3. 真实文字、flex/grid、明确 padding/gap、CSS token、语义容器。从同版本 tokens 和组件约定生成样式，禁止每页重定义相近主色或圆角；局部差异写入例外。为页面和重要元素建立稳定 ID，维护 viewId→源页面→远端画板映射。为 Penpot 保留文字、边界、层级和样式，不能只留截图。
4. 渲染，等待字体素材加载，逐页查截断、错字、重叠、滚动裁剪、密度和参考差异，检查约定终端及必要窄屏。同时检查实际颜色对比、键盘/focus、约定状态及可访问性目标，未验证的项目如实记录。与规范逐项核对，修复后再上传。

## 图层要求

- 文字保留内容、family、weight、字号、行高、字间距、字色和对齐；混合样式保留分段。
- 容器保留宽高、父子、padding/gap、方向、对齐、圆角、填充、描边和效果。转换丢失语义须补说明并披露。
- 图标优先矢量；照片可作独立图片。完整页面或带文字组件不可栅格化冒充分层结果。
- 复杂效果先验平台兼容，不支持时针对替换并记录。
- 组件、变量和复用按平台能力落实。宿主设计技能若强制原生组件重建，必须遵守，不以捕获或截图规避。
- 用户需可见标尺/注释时另建说明区域；原生属性是基础，不以画尺子代替。

## 验收与衔接

先做本地需求覆盖及视觉检查。远端交付后检查远端结构、数值及查看者，见[验收格式](../evidence.md)。可运行：
使用[兼容说明](../runtime-compatibility.md)中探测到的 Python 3.9+：macOS 通常为 `python3`，Windows 通常为 `py -3` 或已确认为 Python 3 的 `python`。将本技能根目录下的 [scripts/verify_delivery.py](../../scripts/verify_delivery.py) 的实际路径及证据 JSON 作为参数传入，不假设某个 shell 或 Unix 可执行位。

脚本只检查证据记录完整性，不代替实际看图、读回和第二账号验证。本地样式不是远端已验证属性，缺证据标待验收。

展示预览、设计说明及规范版本/复用入口，再选择是否上传；上传同时持久化可编辑规范区域并读回，上传后回写链接与差异，细节按项目规范约定。补充/修改复用前置目标，不重新索取链接或首次询问风格。本地保存按用户选择，不擅自发布 HTML 网站替代设计平台。
