# Ardot 自动交付

选择 Ardot 后必须读取本文件并执行[云端交付](../cloud-handoff.md)，问答遵守[统一协议](../interactive-input.md)。交付是可编辑的原生设计图层及规范；本地 HTML、整页截图、空文件或仅打开网页均不能替代。由[前置上下文](../design-context.md)调用时只连接、授权和读取，不创建或修改云端内容。

## 连接：云端优先，无需本机客户端

1. 复用真实可用的 Ardot 连接；先读取当前工具契约与目标身份。未连接时发现宿主的受管连接/自定义 MCP 入口。WorkBuddy 已声明服务先走[原生连接引导](../workbuddy-input.md#平台选择后的连接引导)，等待卡片结果，不另开一套认证绕过失败或取消。
2. 没有受管候选时，核查所选宿主是否可添加官方远程 HTTP MCP：`https://ardot.tencent.com/mcp`。官方示例服务名为 `ardot-remote`；新增自定义条目时可采用该名称，已有条目复用真实名称。该示例名不是宿主已经声明的 servers 标识，不可凭空传给连接工具。
3. 根据[宿主评估与接入](../ardot-capability.md)和当前宿主 schema，自动添加或打开实际配置入口，只合并本服务条目，保留其他 MCP。遵守宿主的配置权限和信任流程；安装器本身不写账号配置。需要重载时保存继续点并说明恢复方式，不假称当前工具已出现。
4. 用宿主正式机制启动 OAuth，打开真实返回的授权页；没有受管等待卡片时，按云端交付提供“完成授权 / 重新打开授权 / 暂不上传”问答。用户处理登录、信任、二次验证和同意授权。不要索取所谓 Ardot MCP key、密码、Cookie 或授权码，也不把 MCP 端点当成授权页面。
5. 授权后重新发现真实工具，验证身份、目标访问及写入路由。远程模式使用真实文件/节点链接绑定上下文；不能因未安装客户端或没有“当前活动文件”就报告失败。账号认证、文件存在、可编辑权限分别记录。

仅当用户已选择本地路线，或远程能力/额度存在具体限制且用户同意改用本地时，才启用 Desktop MCP。它要求 Ardot 客户端已打开目标文件；官方默认端点 `http://127.0.0.1:50501/api/v1/mcp`，端口占用会变化，应读取实际配置，不扫描任意端口或假定默认可达。本地路线失败不能否定云端路线。用户拒绝授权后不换路线绕过。

## 创建、命名与绑定目标

- 新建优先用当前 MCP 实际提供的文件创建能力，自动生成业务文件名并记录返回链接和稳定 ID。官方文档支持通过云端 MCP 创建文件，但工具名与参数会更新，先发现 schema，不虚构 `create_file` 或复制 Figma API。
- 当前连接只提供画布写入时，由智能体用可控浏览器创建、命名文件，取得真实链接后交给 MCP；不要求用户手动建文件或导入。两条路线确实不可用时报告缺的是文件创建能力，保留平台和设计，不谎称上传完成。
- 已有项目/文件/画板按[追加规则](../cloud-handoff.md#补充已有设计先定位再追加)处理，默认新增文件/页面/独立区域；保留旧节点与权限。生成前已读取的风格只在发生相关漂移时局部调整。
- 每批写入前验证绑定的文件/页面/父节点身份；本地 MCP 还要核对活动文件。真实 ID 优先于名称，不向碰巧打开的另一文件写入。

## 原生构建与素材

- 使用实际画布写入工具，从已验收的设计文档、布局、tokens 和 viewId 构建 Frame、文本、布局、矢量、组件及独立内容图片。此处“上传”是直接写入 Ardot，无需先创建 Figma 文件或伪造 `.fig`。
- 原生变量/组件能力存在时采用真实引用；平台无法表达的规则放入可编辑规范区域并记录差异，不悄悄修改全局值。工具支持批量编辑时分容器/业务视图写入，记录返回节点 ID。
- HTML 不是已验证的 Ardot 原生导入格式。不得声称上传 HTML 即得到分层文件；`.fig` 导入只在已有真实文件、宿主具备导入能力且用户授权该路线时采用，导入后仍须逐项验收。不要把选择 Ardot 推断为允许另外写入 Figma。
- 本地素材使用工具实际支持的上传通道或可控浏览器；不假定云端能读取本机路径，不擅自使用公共图床。素材缺项单独记录。
- 写入遵守实时额度与错误返回，按业务块减少调用；限流时保留进度，遵守平台重试时间，不密集重试。核对时云端 MCP 公测限时免费，每分钟 20 次、每日 600 次，后续可能调整或收费；不承诺永久免费，不自动升级。可编辑权限才能读写画布，查看权限不能代替编辑权限。

## 远端验收与恢复

按[共同验收](../evidence.md)实际读回每个 viewId 的原生文字、容器和关键属性，再检查远端渲染截图、字体、素材及覆盖范围。追加/更新还须核对原有范围的基线。按[项目规范约定](../project-style-contract.md)保存可编辑规范区域，读回完整规则/token，并回写真实链接、版本、节点映射及差异。

返回工具/浏览器实际取得的 Ardot 文件和关键画板链接，不拼接猜测链接。未验证第二账号的查看、属性检查、测距及代码复制时标为待验收，不沿用其他平台的免费权益承诺。原生文件导出仅在真实支持并成功后交付，不猜测扩展名。

中断后先读回真实 ID，只补缺失内容；超时结果不明保持 pending，不重复创建文件。明确根因修复后最多重试两次，宿主对取消/失败更严格时遵守宿主规则。只有内容、规范和远端读回均通过，才可报告已上传并检查。
