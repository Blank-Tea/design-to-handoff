# Figma 交付方案

这是 design-to-handoff 的内部阶段说明。需要用户输入时遵守[内置问答约定](../interactive-input.md)，沿用当前阶段、待答问题和已有答案。

只在用户选择 Figma 后上传。不默认购买会员，原始文档不上传。输入为已验收的源页面、规范、viewId 清单，以及明确或待选择的目标位置。

## 能力预检与连接

1. 发现当前 Figma 工具及真实参数；已有连接复用。没有连接时通过宿主插件/授权流程连接，不能假设一个叫“授权”的工具必然存在。
2. 只读确认账号、套餐、目标编辑权限。Code to canvas 官方说明支持 Starter；原生画布写入 use_figma 是另一条路径，不能把两者权益混用，也不承诺未来永久免费。
3. 优先复用目标 Design 文件；能真实列出项目时只展示可写项。没有枚举工具时不伪造目录，问目标文件/项目链接，或说明将新建个人草稿。多团队让用户选；已有唯一团队且允许草稿落点则继续。
4. 新建文件前加载可用的 figma-create-new-file 技能并遵守其账号/planKey 规则。fileKey 确定后若有 create_session，创建并沿用返回 sessionId。工具要求现有文件就先建文件，不照抄官方页面中不同客户端的参数。

## 免费优先：Code to canvas

- 输出必须是 editable Design layers。已有静态 HTML 且提供 html_to_figma 时，遵守当前工具契约转换；没有该工具，不虚构调用。
- 可运行页面通过 generate_figma_design 捕获。本地服务仅提供本次设计目录，默认绑定回环地址，不把需求目录或整个工作区作为静态站点根。
- 先读取当前工具返回的捕获说明、脚本和 captureId，再按要求执行；只在本次本地设计页面注入脚本，遵守浏览器工具的操作边界。捕获接口需要远端可访问地址时先说明，不自动公开部署文件。
- 为每个 viewId 捕获正确视口和状态。默认每页/状态对应一个画板；如果连接器每次新建 Page，会消耗免费页数额度，优先用真实支持的目标节点/同页多画板方式；额度不足说明并让用户选拆文件或减少本次范围，不自动付费。
- 轮询遵守工具契约和宿主等待限制，按返回状态处理，不自行编造上传成功。已消费 captureId 不反复用于新捕获，批量部分失败只补缺页。
- 捕获得到的层可能没有组件库绑定。最终编辑性、层级和样式必须实查，不能仅因官方称“设计图层”就验收。

## 宿主技能兼容

调用工具前加载其要求的现有 Figma 技能（例如 code-workflows、generate-design、use）。某些版本要求捕获结果只作参考，必须以原生组件重建，并删除参考捕获；另一些版本支持直接把转换层作为交付。以当前宿主要求为准。

若必须原生重建，先确认 use_figma 权限并执行组件/变量构建要求。免费账号不能满足时标明受阻，提出保持免费改用 Penpot或允许的手动导入，不暗中放宽验收、不假称全自动成功、不自动买席位。

## 图层与数值验收

按[共同验收标准](../evidence.md)检查：
- 每个 viewId 对应的真实文件/画板 ID，以及文字、容器、图标等节点类型。
- 独立文字仍是 TEXT，按钮文字可单独选中，无整页 UI 图片藏在交付画板内。
- 读回关键文字的 font family/size/weight/line height/color，容器的边界、圆角、填充及可用布局属性；与设计规范比较。无法直接保留 padding/gap 时补布局说明并披露转换差异。
- 保存一张整体构图截图检查视觉，修复明确问题后再截图，不对未改结果不断重复截图。
- 通过元数据/原生属性或实际 UI 检查，不能让本地 CSS 冒充云端值。权限受限无法验证时保留待验收状态。

## 多人查看与代码标注

优先沿用文件查看权限或邀请用户指定账号；不要为方便自动公开全部文档。返回 Design 文件/画板链接，不只返回原型链接。

免费查看者可在设计模式选中对象，通过 Properties 看样式，用 Option/Alt 测距，用右键 Copy/Paste as → Copy as code 获取样式。不能把高级 Dev Mode 当免费查看的必要条件。

要声称多人验收通过，需用第二个没有付费席位的查看账号实际打开最终链接，检查文字/容器并复制一段样式，记录真实结果。不具备第二账号就注明“本人检查通过，多人查看待验证”，不借用他人凭证。

## 本地保存与后续更新

用户选保存时保留源页面、规范、预览及证据；导出原生文件以实际能力为准。更新设计优先修改源页面并在新版本区捕获，保留旧画板直到新版本验收，不擅自删除已有设计。已确认需要原生组件重建时按宿主要求更新，而非用再次捕获规避。
