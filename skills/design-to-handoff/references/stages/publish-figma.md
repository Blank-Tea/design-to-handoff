# Figma 自动交付

这是 design-to-handoff 的内部阶段。选择 Figma 后执行[云端交付流程](../cloud-handoff.md)，问答沿用[统一协议](../interactive-input.md)。默认是可编辑 Design 图层，已在主入口确认，不再让用户在 Code/Make 与 Design 之间重新选择。

## 浏览器授权与能力验证

1. 发现当前 Figma 插件/MCP、浏览器和宿主连接入口。通过真实身份工具（例如 whoami）探测现有连接；成功则复用，失败则由宿主启动官方授权流程，并打开真实返回的授权页/连接页。
2. 授权页打开后发起原生问答：“请完成 Figma 登录及授权，然后选择‘完成授权’。”选项为“完成授权”“重新打开授权”“暂不上传”，允许自由输入问题。接收回答后立即重新探测；只有身份和工具访问验证成功才能继续。浏览器已登录不等于 MCP 已授权。
3. 官方远程服务地址是 `https://mcp.figma.com/mcp`，这是 MCP 端点，不是可直接冒充授权页的 OAuth URL。使用宿主正式连接机制；不要求用户创建自己的 OAuth 应用或把个人令牌贴进聊天。
4. 分别检查创建文件、读写节点、上传/捕获及浏览器能力。不能把只有读取功能的 REST/MCP 连接当成具备画布写入权限；免费/席位/受支持客户端限制按实际返回处理。不自动购买、升级或改分享权限。

## 新建设计：创建、命名与上传由智能体完成

- 身份工具返回一个可用 plan 时采用其 key；返回多个时用原生问答选择真实团队/组织，沿用用户已给 planKey。文件名从当前项目生成，用户已给名称则采用。
- 提供 `create_new_file` 时，先加载宿主要求的 figma-create-new-file 技能，传真实 planKey、自动文件名、`editorType: design`，有已确认的项目时另传 projectId。默认可放选定账号的草稿区，不要求用户先建文件夹或 Design 文件。
- 某些客户端的捕获工具自身支持新文件模式，则按其实际 schema 自动创建；当前工具若必须提供 fileKey，先由创建工具或可控浏览器创建文件，不能把这个前置步骤交回用户。浏览器创建后读回真实文件身份和链接。
- 用户明确要一个新的团队 Project/目录时，用实际管理工具或可控浏览器创建。缺少这项能力但可以创建草稿文件时，在问答中展示具体替代落点；不得把草稿文件称为已新建 Project。
- fileKey 返回后按宿主要求创建并沿用文件会话。记录创建返回的 ID，续传复用，不反复创建同名空文件。

## 已有项目、文件与画板

先按[追加设计规则](../cloud-handoff.md#补充已有设计先定位再追加)解析并读回目标身份：

- 项目链接：提取并验证实际 projectId，在该项目中自动新建 Design 文件，不要求用户手动导入。
- Design 文件链接：绑定 fileKey，读回已有页面、相关样式/组件及本次范围，默认新增业务页面；页面额度不足先说明在现有页面追加区域的方案。
- 页面或画板链接：验证 nodeId 所属文件与页面，在不重叠的区域新增独立画板，保留原节点。链接锚点不代表允许替换。
- 明确更新原画板时，只修改已授权范围；目标或覆盖范围不清时，先列真实候选及差异再问。不能把“补充”当作删除或覆盖授权。

若用户在设计生成前已提供目标，提前只读吸收其样式；到上传阶段才提供目标，先按共同流程比较已验收设计与既有风格。实质冲突先展示局部差异和预览并用问答确定取舍，再调整受影响部分；已有明确授权时沿用，不重跑完整访谈。多文件任务的会话约束按当前工具说明执行，不猜测 sessionId。

## 写入路由

按当前宿主工具与强制技能选路线，不要求用户自己执行导入：

- 提供原生 `use_figma` 等写入工具时，加载所要求的 figma-use、generate-design 等指导，用真实文字、容器、组件、变量和图标构建页面。
- 提供静态 HTML 转换时，按实际支持的工具转换，并实际检查其结果是否为 Design 图层。不能为了绕过宿主要求，直接交付未绑定组件的参考捕获。
- Web 首次捕获可按当前工具协议使用 `generate_figma_design`：本地页面由智能体启动服务、注入真实返回的捕获脚本、轮询并核对结果。当前工具要求 fileKey 时传已创建文件，要求 nodeId 时用已确认落点；不能擅自为每个视图新建 Page 消耗额度。
- 宿主要求捕获仅作参考、同时用原生组件重建时必须执行，删除的仅是本次参考捕获。更新已经存在的页面按当前工具要求使用原生写入，不反复捕获覆盖旧页。
- 远程连接器无法访问 localhost、不能导入本地素材时，先使用工具真正支持的资源上传或浏览器操作，不擅自公开发布整个工作区。没有可用写入路由时给原生问答选择连接写入工具、修复连接或暂缓，不能默认降级成“请自行导入”。

## 验收与完成

依据[共同验收](../evidence.md)读回每个 viewId 的实际页面/画板、文字和容器属性，检查远端截图及加载完成后的字体/素材。追加任务还核对原有范围的基线，发现意外改动先修复。

返回 Design 文件和主要画板链接，可在浏览器显示最终文件；“文件已创建”与“内容已上传”分开说明。免费查看者可看基础 Properties、测距和复制样式，第二个免费账号未实测时保留“多人查看待验证”，不以高级 Dev Mode 作为免费交付的必要条件。

部分写入失败先读回真实 ID，只补缺失视图，遵守主入口的重试上限。用户已选择的本地保存策略继续有效，原始私人需求文档不上传。
