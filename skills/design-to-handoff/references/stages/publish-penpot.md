# Penpot 交付方案

这是 design-to-handoff 的内部阶段说明。需要用户输入时遵守[内置问答约定](../interactive-input.md)，沿用当前阶段、待答问题和已有答案。

只在用户选择 Penpot 后上传。输入与 Figma 共用需求、规范、viewId 和源页面。不要将整页 PNG 或转曲 SVG 当作含字体属性的完整交付。

## 一次性连接

先发现真实工具，复用已有连接。未连接时按平台当前官方方式引导：
1. 注册/登录 Penpot 免费云账号，或使用用户指定的自部署实例。
2. 官方远程 MCP：账号 Integrations → MCP Server 开启；按页面生成 MCP key，将含密钥的服务器 URL 配置到宿主 MCP 设置，使用宿主秘密存储。不要让用户把密钥贴进聊天，也不要输出完整含密钥 URL。
3. 用户在目标项目创建/打开设计文件，通过 File → MCP Server → Connect 连接。当前标签页保持活跃，避免休眠。
4. 若当前版本只有本地 MCP，则使用官方当前安装方式；安装或更改配置属于必要初始化，但应展示具体配置再按宿主权限执行。不要自行固定生产服务器地址、用伪令牌连接，或不经授权替用户安装。

参考[官方 MCP](https://help.penpot.app/mcp/)。不能仅因为服务已配置就假设本次会话已暴露工具；工具仍缺失时，明确请求用户刷新连接/新会话，不在当前会话伪造工具。

## 目录与文件选择

有真实项目/文件枚举能力时展示可写项目及文件；没有则请用户在目标项目打开文件并连接，记录可验证的文件链接。官方 MCP 通常操作当前聚焦页面，不能承诺可以枚举全部项目或后台任意切换文件。

读取实际文件/页面身份，与用户目标核对。标签页切换后必须重新核对，不向“碰巧当前打开”的文件写入。用户已明确“用当前文件”且身份可读时继续，不多问一次许可。

## 原生构建

1. 使用实际提供的 overview/API 信息工具了解页面、节点及可用 API；常见工具名称包括 high_level_overview、penpot_api_info、execute_code，以实际 schema 为准。不要把 Figma Plugin API 语法直接用于 Penpot。
2. 从已渲染源页面和规范提取内容、尺寸及样式，创建原生 boards/容器、文字、矢量与离散图片，维护 viewId 和元素映射。先构建一个有代表性的标题、文字按钮及布局，确认字体与属性正常再扩展。
3. 按稳定业务语义命名页面、画板、组件及图层；尽量复用组件和 token。至少保持文字与背景独立，可查看字体、颜色、圆角、间距。真正不支持的布局语义写在说明区并披露。
4. 参考图不导入最终画板作底图。SVG 只用于离散矢量图标等；把全部文字转路径会丢失字体标注，不接受。
5. 写入使用可恢复小批次，保留实际 ID；用现有节点检查防重复。失败先读回确认部分写入，不盲目重建。
6. 素材导入按当前本地/远程工具能力选择。远程 MCP 未提供本地图片导入时，不虚构 import_image；采用真实支持的上传方式，或说明需本地 MCP/用户操作。禁止为图片可访问而擅自上传公共图床。

## 验收与交付

按[共同验收](../evidence.md)逐页检查原生层、实际文字属性、尺寸/布局、圆角/颜色及整体视觉。导入成功不等于数据已正确同步到云端；刷新或重新读取确认已持久化。

分享目标是带 Inspect 的设计/查看链接。使用真实分享工具（如果存在），或引导用户在文件分享界面开放指定查看者，并启用 Inspect/代码查看所需选项。不要默认所有原型预览链接都允许检查图层。

验证第二个免费查看账号可打开最终链接、Inspect 测距、查看文字样式、复制 CSS/HTML/SVG 样式片段。没第二账号则保留待验收，不能声称多人实测通过。

导出本地 .penpot 只在用户选择本地保存且真实导出成功时进行，不把 zip/图片改后缀。平台 API 没导出入口时可说明可由 UI 导出，未导出不假装完成。
