# Penpot 自动交付

这是 design-to-handoff 的内部阶段。选择 Penpot 后执行[云端交付流程](../cloud-handoff.md)，使用[原生问答](../interactive-input.md)。这里的上传是创建真实文字、容器、矢量和独立图片，不把整页 PNG 或转曲 SVG 当作可检查的分层设计。

## 浏览器登录与问答密钥配置

1. 发现当前 Penpot 连接、浏览器和宿主 MCP 配置能力，先做只读探测。已有连接与密钥有效时直接复用，不重复询问。
2. 没有有效会话时，用可控浏览器打开真实 Penpot 实例：用户已给自部署地址则采用；否则使用官方 SaaS `https://design.penpot.app`。让用户完成登录及账号确认，智能体不读取登录凭据。
3. 首次使用远程 MCP 或密钥失效时，单独发起原生问答 **【Penpot MCP 密钥｜必填】**：“请输入用于连接当前 Penpot 实例的 MCP 密钥。尚未生成时，可在已打开的账户 Integrations → MCP Server 页面启用并生成。”在宿主支持时采用秘密输入；不支持时按用户明确要求使用专门的自由文本题，不与设计需求或其他字段合并。可以回答稍后提供/暂不上传；未给真实密钥不能视作已连接。
4. 优先接收密钥本身；用户给了完整 MCP URL 时仅在内存提取实例地址与 userToken，不输出完整 URL，也不把秘密留在交付记录。自部署实例尚不明确时另问公开实例地址，不把 MCP key 与登录密码、个人访问令牌或普通分享链接混为一谈。
5. 接收后，用所选宿主的秘密存储或用户级 MCP 配置自动建立连接；范围仅是用户本次选择的宿主和 Penpot 实例，不修改其他账号连接。配置方式与位置先作简短说明，受宿主审批约束时走其原生审批。不把密钥写到项目仓库、设计目录、shell 命令参数或运行日志中。没有安全配置通道时，打开宿主实际的秘密/连接设置并继续同一问答流程；不要把密钥打印出来让用户复制。
6. 配置完成后发起“请完成 Penpot 登录/连接授权，然后选择‘完成授权’”，选项“完成授权”“重新打开连接页”“暂不上传”，保留自定义输入。收到完成事件后实际重新发现工具并探测。用户已填密钥且探测已自动成功、账号也已确认时可直接继续，避免多问一次空确认。

官方远程 MCP 当前使用个人 MCP key，且每个账号通常仅有一个 key；复用现有有效 key，不擅自轮换或撤销。技能不能把它伪装成统一 OAuth。秘密输入、MCP 配置和浏览器登录是三个不同能力；不能仅因用户点了“完成授权”就宣称三者均成功。

## 自动创建目标并连接文件

Penpot MCP 通常只操作当前聚焦页面，不能假定能枚举全部项目或创建任意文件。新文件尚不存在时，插件没连接不是需要无限重做账号授权的理由：

- 账号/团队已确认后，用真实项目管理工具或可控浏览器选择可用项目、创建并命名文件。只有一个合理可写项目时直接采用；多个团队/项目且未指定时在问答中列真实选项。用户要求新 Project 时由智能体创建，不让用户自己建目录。
- 默认名称来自当前项目和业务页面；缺名称不阻塞。记录新 projectId/fileId/pageId 与真实链接。
- 文件创建或定位后，由智能体打开它，并通过可用的浏览器操作 File → MCP Server → Connect 等非敏感连接步骤。浏览器标签页保持活动；不要求用户手动导入设计文件。
- 配置密钥和登录是用户必要输入，建文件、命名和构建设计仍由智能体负责。如果当前宿主只有页面 MCP 且没有任何可用浏览器/管理工具，则明确缺的是“自动创建目标文件”的能力，保留设计并让用户选择补齐工具或暂缓，不能把手动步骤当成已完成自动上传。
- 工具要求本地 MCP 时按当时官方能力选择，不默默安装长期后台服务；已有配置和所需用户级连接设置在用户提供密钥及选择平台的范围内完成，其他初始化遵守宿主权限。

## 补充已有项目/文件

按[追加设计规则](../cloud-handoff.md#补充已有设计先定位再追加)接收真实链接并读回：项目链接默认在该项目新建文件，文件链接默认新增业务页面，页面/画板链接默认新增独立区域。既有页面、组件、图层和权限保留；明确要求更新时才修改对应范围。

先取得本次相关样式、组件、字体和布局约束。与已验收设计发生实质冲突时，按共同流程展示局部差异及预览，通过问答或既有明确授权确定取舍后再调整；不能静默改变已验收方案。MCP 连接绑定实际 fileId/pageId；每批写入前重新比对。用户切换标签页或当前文件时，智能体定位回已授权目标并验证，再继续写入，不向“碰巧当前打开”的文件落图。

## 自动构建与恢复

- 使用实际 overview/API 信息工具理解当前页面及可用操作，再用真实 execute_code 等工具创建页面/boards、文字、容器、矢量和内容图片。不要照搬 Figma Plugin API 语法或虚构 create_project/import_image 工具。
- 先验证一个代表性文字、按钮和布局的字体及属性，然后分批构建其余视图。按业务名称命名，维护 viewId → 节点 ID，不靠同名判断可覆盖。
- 新增区域避开已有画板；复用已有组件和 token，不修改全局共享样式来迁就本次新增设计。
- 官方远程 MCP 不能直接从本机路径 import_image；使用实际支持的上传通道或智能体可执行的浏览器素材导入。没有可用通道就报告具体素材缺项，不把素材传到公共图床。
- 部分写入失败先读回，只补缺失节点或视图，复用已创建文件。目标上下文丢失时先恢复连接，不再建一个同名文件来绕过问题。

## 验收与完成

按[共同验收](../evidence.md)核对真实页面、文字/容器类型、关键属性及远端整体预览；刷新或重新读取确认已持久化。追加任务还对照原范围基线，修复意外改动。

返回真实文件/页面链接，可在浏览器显示最终文件。第二免费查看账号未实测时注明待验收，不把链接可打开等同于 Inspect、测距和代码复制已通过。原生 .penpot 导出只按实际能力和本地保存选择提供，不能重命名其他格式冒充。
