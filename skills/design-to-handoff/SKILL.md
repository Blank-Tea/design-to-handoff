# 需求到分层设计交付

## 使用方式

对外只提供 design-to-handoff 一个技能入口。按阶段读取下表中的内部说明文件，在同一流程内执行，不另外调用或注册这些阶段为 skill，不需要新聊天或并发代理。

需求、方向、参考、设计及平台交付继续分文件维护，但放在本技能的 references/stages/ 中，均为普通 Markdown；这些模块不带 SKILL.md、独立技能元数据或 agents 入口。安装与分发只复制完整的 design-to-handoff 文件夹，包含 references/、scripts/ 和入口配置。

面向用户统一称 design-to-handoff。进度用“整理需求”“确定设计方向”“分析参考”“生成设计”“交付 Figma/Penpot”等业务阶段，不播报内部模块名、路径或“切换/调用子 skill”。用户明确询问实现细节时可说明；遵守宿主对外部必需技能的披露要求，不承诺隐藏宿主工具执行记录。

交付对象为含真实文字、容器、矢量和内容图片图层的在线设计文件。整页 PNG、PDF、画在图片上的红线、Code/Make 运行预览都不能代替分层文件。代码标注是元素样式片段，不是完整业务代码。

## 提问节奏

以下是**所有智能体宿主共用的交互规则**，适用于 Codex、Claude Code、CodeBuddy（插件/IDE/CLI）、Cursor、OpenCode 及其他兼容宿主；不是某一产品的可选特例。开始收集输入前读取[内置问答约定](references/interactive-input.md)，本入口及所有内部阶段统一遵守。

需要询问用户时，必须优先使用当前宿主可用的原生结构化问答，提供可点击选项和自定义输入；不要用 final/完成工具或纯文本菜单代替可用的问答控件。开放的文档地址使用独立输入题；宿主要求题目必须带选项时保留其原生自定义输入入口。用户回答后在当前流程自动继续，不要求再说“继续”或重新调用 skill。各宿主只适配工具名称、参数和等待方式，不改变提问顺序、必填性、跳过规则及单入口。确实没有可用原生问答时，明确说明当前能力缺口后才降级，不能默默改为纯文本提问。

每阶段按工具容量合并问题，复用已知信息，不一口气索取全部问卷。用户说“你推荐”时采用并说明建议；可选项提供“跳过”。必要回答缺失保持待答，不能把超时、默认预选或工具返回空值当成答案。

所有宿主的首次文档收集均拆成两道独立问答，按顺序发起；不要合并成一个文本框，也不要要求用户按“需求：…；补充：…”填写：
1. **【需求文档】必填**：收集实际文件路径、目录、在线链接或已提供附件。没有有效来源时留在本题，不能用空值、“跳过”、选项标签或 AI 推荐替代。
2. **【补充文档】可选**：需求来源确定后单独询问，提供“跳过（无补充文档）”及填写地址的方式。用户明确跳过、回答“无”或主动提交空白可选题后继续，不强求补充文件；未作答与已提交空白要区分。

复用已提供的文档及明确的“无补充”选择，仅询问缺失题。地址可以是文件、目录或在线链接；不要只收集“本地/在线”类型。多版本目录用真实候选作为后续选项。CodeBuddy 插件必须按[插件问答适配](references/codebuddy-plugin-input.md)调用其原生提问工具。

不将技能创建者在其他聊天中的业务、语言和设计偏好视为本次需求。

## 宿主与操作系统

本技能应在 Codex、Claude Code、CodeBuddy 等支持 Agent Skills 的宿主中使用，不依赖作者本机。第一次运行按[运行兼容说明](references/runtime-compatibility.md)识别宿主、操作系统与工具。使用宿主自身的提问、读文件、浏览器和 MCP 能力，按实际暴露的工具及模式限制选择问答接口。Windows、macOS Intel 和 Apple Silicon 共用同一份正文；不强制使用 Bash、macOS 桌面自动化或某个芯片专用程序。

## 按顺序执行

| 阶段 | 读取并执行 | 完成条件 |
|---|---|---|
| 1 需求 | [需求整理](references/stages/intake.md) | 展示浓缩需求、来源和重要未决问题 |
| 2 方向 | [设计方向](references/stages/direction.md) | 必要设计方向已回答或授权推荐 |
| 3 参考 | [参考分析](references/stages/reference-analysis.md) | 已分析参考或明确跳过 |
| 4 保存选择 | 本入口下文 | 知道是否保留本地交付副本 |
| 5 设计 | [设计生成](references/stages/compose.md) | 正式文档、预览和需求覆盖已核对 |
| 6 平台选择 | 本入口下文 | 选择 Figma、Penpot、两者或暂不上传 |
| 7 平台交付 | [Figma](references/stages/publish-figma.md) / [Penpot](references/stages/publish-penpot.md) | 分别记录上传、图层与查看者检查结果 |

摘要展示后直接问设计方向，允许用户同时纠正摘要，不为每个已明确步骤增加确认。先问清改变主要流程、权限或页面的冲突。

## 可选本地保存

参考分析之后、生成之前用内置问答提供“不保留本地副本”“保留到指定目录”，并允许自由输入目录。默认交付内容包含设计文档、规范、HTML/CSS、预览和交付记录。选保留但未提供目录时，在同一问答流程补问目录。

明确选择不保留才不写本地交付副本；未回答保持待答，不自动保存到桌面。允许在许可的临时目录渲染、转换、检查；成功后只清理本次创建且不再需要的临时文件。上传受阻且没有副本时，说明临时文件仍在，询问保留位置或改选平台，避免丢失。不要承诺删除宿主聊天、系统缓存和平台云文件。

指定目录后创建项目子目录，不覆盖同名文件；权限不足使用宿主审批机制。原生 .fig / .penpot 只有真正导出成功才列入交付，不重命名其他格式冒充。

## 平台与权限

可提前只读发现工具并告知未连接，但保持“先设计、后选上传”顺序，不提前创建云文件或要求同时授权两平台。

完成设计后用内置问答提供 Figma、Penpot、两者或暂不上传，并允许自由输入目标链接。选项数受限时按[内置问答约定](references/interactive-input.md)分组，不用文字菜单冒充可点击选项。优先免费能力；能列出可写项目时展示列表，不能时可给目标文件/项目链接，或使用可用的个人草稿/当前文件。

菜单中说明各平台具体默认落点。用户选择即授权上传本次设计至该落点，不重复请求相同许可。明确目标优先；目标不明、当前文件不符或变更已有分享范围时先问清。免费受阻不自动购买、升级、调用收费生成或转传另一平台。

复用已有连接，未连接使用宿主授权界面或对应平台内部说明中的初始化步骤。技能文本不能产生 OAuth 弹窗、安装工具或创造接口能力。密码、Cookie、令牌及含密钥的 MCP URL 不写入聊天输出、设计文件和交付记录。

默认沿用文件权限或向用户明确指定的账号开放查看。公开链接和扩大分享范围先让用户选择；不通过邮件/聊天工具发送消息。原始需求文档不默认上传，远端只放派生设计与必要说明。

## 状态与完成

按[会话记录约定](references/session-contract.md)维护信息，可在会话内；未选保存不写持久检查点。需求变更仅重做受影响阶段。两平台共用一版需求、规范和 viewId。

记录每次云写入返回的文件/节点 ID。部分失败先读回再续写，修正根因后最多重试两次；仍失败保留具体阻塞和继续点，不盲目制造重复文件。

分别报告：仅本地完成、已上传但标注待验收、本人检查通过但多人查看待验收、多人标注交付验收通过。给出真实链接、覆盖页面及缺项。没有第二账号验证，不声称多人查看已实测。

本包是两套交付方案，不表示当前账号已接通。执行时以真实工具契约、宿主技能约束和官方权益为准。
