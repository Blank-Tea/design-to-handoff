# 需求到分层设计交付

## 使用方式

对外只提供 design-to-handoff 一个技能入口。按阶段读取下表中的内部说明文件，在同一流程内执行，不另外调用或注册这些阶段为 skill，不需要新聊天或并发代理。

需求、方向、参考、全局设计基础、设计及平台交付继续分文件维护，但放在本技能的 references/stages/ 中，均为普通 Markdown；这些模块不带 SKILL.md、独立技能元数据或 agents 入口。全局设计基础是流程内的补充模块，不要求用户另装或调用第二个 skill。安装与分发只复制完整的 design-to-handoff 文件夹，包含 references/、scripts/ 和入口配置。

面向用户统一称 design-to-handoff。进度用“整理需求”“确定设计方向”“分析参考”“确定全局设计基础”“生成设计”“交付 Figma/Penpot”等业务阶段，不播报内部模块名、路径或“切换/调用子 skill”。用户明确询问实现细节时可说明；遵守宿主对外部必需技能的披露要求，不承诺隐藏宿主工具执行记录。

交付对象为含真实文字、容器、矢量和内容图片图层的在线设计文件。整页 PNG、PDF、画在图片上的红线、Code/Make 运行预览都不能代替分层文件。代码标注是元素样式片段，不是完整业务代码。

## 提问节奏

以下是**所有智能体宿主共用的交互规则**，适用于 Codex、Claude Code、CodeBuddy（插件/IDE/CLI）、WorkBuddy、Cursor、OpenCode 及其他兼容宿主；不是某一产品的可选特例。开始收集输入前读取[内置问答约定](references/interactive-input.md)，本入口及所有内部阶段统一遵守。

需要询问用户时，必须优先使用当前宿主可用的原生结构化问答，提供可点击选项和自定义输入；不要用 final/完成工具或纯文本菜单代替可用的问答控件。开放的文档地址使用独立输入题；宿主要求题目必须带选项时保留其原生自定义输入入口。用户回答后在当前流程自动继续，不要求再说“继续”或重新调用 skill。各宿主只适配工具名称、参数和等待方式，不改变提问顺序、必填性、跳过规则及单入口。确实没有可用原生问答时，明确说明当前能力缺口后才降级，不能默默改为纯文本提问。

每阶段按工具容量组织问题，复用已知信息，不一口气索取全部问卷。全局设计基础将相近参数合为一组，一次问答确定一组；不同维度分开询问，不因工具能容纳更多题而混在同轮。支持本组采用推荐、指定某项其余推荐或剩余全部推荐；其他阶段可按工具容量合并。用户说“你推荐”时采用并说明建议；可选项提供“跳过”。必要回答缺失保持待答，不能把超时、默认预选或工具返回空值当成答案。

所有宿主的首次文档收集均拆成两道独立问答，按顺序发起；不要合并成一个文本框，也不要要求用户按“需求：…；补充：…”填写：
1. **【需求文档】必填**：收集实际文件路径、目录、在线链接或已提供附件。没有有效来源时留在本题，不能用空值、“跳过”、选项标签或 AI 推荐替代。
2. **【补充文档】可选**：需求来源确定后单独询问，提供“跳过（无补充文档）”及填写地址的方式。用户明确跳过、回答“无”或主动提交空白可选题后继续，不强求补充文件；未作答与已提交空白要区分。

复用已提供的文档及明确的“无补充”选择，仅询问缺失题。地址可以是文件、目录或在线链接；不要只收集“本地/在线”类型。多版本目录用真实候选作为后续选项。CodeBuddy 插件按[插件问答适配](references/codebuddy-plugin-input.md)，WorkBuddy 按[桌面端适配](references/workbuddy-input.md)调用各自的原生问答工具。

不将技能创建者在其他聊天中的业务、语言和设计偏好视为本次需求。

## 宿主与操作系统

本技能应在 Codex、Claude Code、CodeBuddy、WorkBuddy 等支持 Agent Skills 的宿主中使用，不依赖作者本机。第一次运行按[运行兼容说明](references/runtime-compatibility.md)识别宿主、操作系统与工具。使用宿主自身的提问、读文件、浏览器和 MCP 能力，按实际暴露的工具及模式限制选择问答接口。Windows、macOS Intel 和 Apple Silicon 共用同一份正文；不强制使用 Bash、macOS 桌面自动化或某个芯片专用程序。

| 2 设计上下文 | [前置上下文](references/design-context.md) | 确认新建/补充/修改；已有链接、基准、关键冲突在生成前确定 |
| 3 方向 | [设计方向](references/stages/direction.md) | 只确定终端、用途与大方向，继承已有约束 |

| 5 全局设计基础 | [基础问答](references/stages/foundations.md) | 参考后按同类参数分组确定或授权推荐；完整规范和 token 已解析，同站设计继承已有版本 |
| 6 保存选择 | 本入口下文 | 知道是否保留本地交付副本；已说明规范的持久落点 |
| 7 设计 | [设计生成](references/stages/compose.md) | 前置上下文 ready；正式文档、预览和需求覆盖已核对 |
| 8 上传选择 | 本入口下文 | 无预连接也先提供平台问答；新建选择平台，补充复用已有目标，确认是否上传或暂缓 |
| 9 平台交付与规范归档 | [云端交付](references/cloud-handoff.md)，再读 [Figma](references/stages/publish-figma.md) / [Penpot](references/stages/publish-penpot.md) | 授权验证、自动建文件/追加、上传及远端读回通过；按[项目规范约定](references/project-style-contract.md)保存可复用规范与真实链接；多人查看单独记录 |

摘要展示后先识别新建还是补充/修改。补充已有设计时，主动在生成前索取尚缺的项目/文件/画板链接，读回样式与组件、解决冲突并固定基准，再进入方向和生成；不能等到上传阶段才首次核对。用户同时可纠正摘要，不为已明确步骤重复确认。

## 可选本地保存

参考分析和全局设计基础确定之后、生成之前用内置问答提供“不保留本地副本”“保留到指定目录”，并允许自由输入目录。默认交付内容包含设计文档、带版本的全局规范、tokens.json、HTML/CSS、预览和交付记录。上传前说明：设计文件中也交付可编辑“设计规范”页/区域，记录全部全局规则与 token，供同站扩展复用。不保留本地副本不等于省略规范；本地、云端和仅聊天交付的持久性区别见[项目规范约定](references/project-style-contract.md)。选保留但未提供目录时，在同一问答流程补问目录。

明确选择不保留才不写本地交付副本；未回答保持待答，不自动保存到桌面。允许在许可的临时目录渲染、转换、检查；成功后只清理本次创建且不再需要的临时文件。上传受阻且没有副本时，说明临时文件仍在，询问保留位置或改选平台，避免丢失。不要承诺删除宿主聊天、系统缓存和平台云文件。

指定目录后创建项目子目录，不覆盖同名文件；权限不足使用宿主审批机制。原生 .fig / .penpot 只有真正导出成功才列入交付，不重命名其他格式冒充。

## 平台、授权与自动交付

新建设计可以先设计、后选择上传平台。补充/修改已有设计必须先按前置上下文收集链接并读取目标，必要的浏览器授权、Penpot 密钥问答及只读连接提前执行；此阶段不创建云文件、不上传、不修改旧内容。确认最终是否上传仍可留到设计验收后。

完成设计后，新建必须先用原生问答选择 Figma / Penpot / 两者或暂缓；尚未连接、未加载平台工具、未配置 MCP 都不能省略或过滤平台选择，不能先以“当前会话没有可用的 Figma / Penpot 连接”结束。平台选择表达交付意愿，不等于宣称已具备写入能力；选定后再发现并建立连接。补充/修改复用已绑定的目标，缺少上传意愿时才问“上传到该目标/暂不上传”。执行[云端交付流程](references/cloud-handoff.md)时只复核身份、权限及相关基线漂移，不首次访谈风格。用户到此时才变更为补充已有目标，按范围变更返回前置上下文，只重做受影响部分。

默认由智能体负责创建云端文件/必要目录、自动命名、上传或原生构建、远端读回及返回链接。不让用户自行新建目录、手动导入或改名来替代自动交付。新建设计默认创建新的设计文件，不把文件与团队 Project 混为一谈；实际创建的目标与权限须有证据。

WorkBuddy 须读取[桌面端连接适配](references/workbuddy-input.md#平台选择后的连接引导)，优先通过 ToolSearch 加载并调用宿主原生 workbuddy_request_mcp_connection，按真实声明标识请求选定平台，不以通用聊天提示代替连接卡片。原生连接卡片已经接管授权等待时复用该卡片及其结果，不额外打开另一套授权流程。没有受管卡片、采用浏览器直连时，由宿主正式连接机制启动授权/登录/连接设置，打开可见浏览器，再用原生问答提供“完成授权”“重新打开授权”“暂不上传”。用户完成后继续本流程，并实际探测账号、连接和目标权限；点击“完成授权”本身不是写入凭据。已有有效连接时复用，不重复授权。

宿主提供受管连接/授权流程时优先交由该流程处理凭证，不额外收集同一密钥；只有无此受管流程且走平台直连方案时，Penpot 首次或密钥失效才单独通过原生问答收集【Penpot MCP 密钥】，优先秘密输入；收到后自动配置所选宿主的连接并验证，不能让用户在设计文件或仓库中存令牌。具体配置按平台内部说明和当前宿主实际能力执行。Figma OAuth 与 Penpot MCP key 不是同一种授权，不能假称一次普通网页登录能代替全部连接配置。

目标落点已说明且用户选择平台/交付方式后，即授权在该落点创建并上传本次设计；不重复审批相同动作。已有项目默认追加，保留原有内容与权限；明确覆盖或删除的范围缺失时先展示具体方案再问。公开分享、扩大权限、付费升级不从上传选择中推断。

不主动回显密钥、含凭证的连接 URL、密码或 Cookie；这些信息不进入源设计、仓库和交付记录。问答提供的 Penpot key 仅用于本次所选宿主连接；其他账号/平台不受影响。无写入能力时先发现可用连接器或浏览器路线，说明缺口并保持可恢复，不能默认把上传任务转交用户后宣称完成。

## 状态与完成

按[会话记录约定](references/session-contract.md)维护流程信息，可在会话内；未选保存不写本地持久检查点。项目规范独立按[项目规范约定](references/project-style-contract.md)随设计交付，上传后回写真实链接、版本及实际差异。后续同站模块先读取此规范及相关设计，只补缺项，不重做整套访谈。需求变更仅重做受影响阶段。两平台共用一版需求、规范和 viewId。

记录每次云写入返回的文件/节点 ID。部分失败先读回再续写，修正根因后最多重试两次；宿主对授权取消/失败有更严格的停止规则时优先遵守；仍失败保留具体阻塞和继续点，不盲目制造重复文件。

分别报告：仅本地完成、已上传但标注待验收、本人检查通过但多人查看待验收、多人标注交付验收通过。给出真实链接、覆盖页面及缺项。没有第二账号验证，不声称多人查看已实测。

本包是两套交付方案，不表示当前账号已接通。执行时以真实工具契约、宿主技能约束和官方权益为准。
